# 比赛演示脚本

## 30 秒讲法

这个系统不是简单生成短视频文案，而是先学习优质样例的创作结构，再把 Hook、节奏、字幕、画面包装、卖点推进和转化方式迁移到新主题中。最后系统会给出多版本方案、质量诊断和竖屏成片预览，帮助创作者选择最值得生产的一版。

## 现场流程

1. 打开首页，先选择“咖啡新品”演示预设，用它播放主推高质量有声视频；如果要讲素材缺口，再切到“学习平板”。
2. 点击“拆解样例结构”，展示系统提炼出的 Hook、节奏和可迁移规则。
3. 点击“生成迁移方案”，展示稳妥转化版、强 Hook 版和内容种草版。
4. 展示时间线草案：每段对应 Hook、证据、收益或 CTA，并标出素材匹配状态。
5. 展示竖屏分镜预览：每段拆成画面层、字幕层、包装层和素材状态，让评委看到成片组织方式。
6. 播放 Remotion 高质量有声成片：最终 15 秒版本会直接在画面里显示“源样例时间段 → 新片段”的手法迁移，例如源 0-3s Hook、源 3-12s 证据推进、源结尾 CTA 收束；节奏、字幕密度、转场倾向、包装标签和补素材说明都来自 `TechniqueTransferRecipe`，说明 AIGC 只补镜头槽位，最终视频由 Remotion 可控重组。
7. 展示迁移映射：样例节拍如何映射到新方案镜头，素材缺口如何补全。
8. 展示素材缺口：哪些结构槽位已有素材支撑，哪些需要包装补全或结构重排。
9. 展示质量诊断：综合评分、推荐主版本、评分维度和优先修正项。
10. 在“自然语言编辑”里输入“开头更强一点，并补充可信证据”，展示系统重写当前方案。
11. 导出 Markdown，说明可以进入 Obsidian 或剪辑团队协作流程。

## 一键全流程演示

如果现场不想完全依赖点击操作，可以先跑一遍端到端脚本生成证据材料：

```bash
npm run demo:final -- \
  --out-dir submissions/final-coconut-latte \
  --asset-manifest outputs/zhipu-video-assets/asset-manifest.json
```

这条链路会完成：样例视频解析 → 整段视频理解（可用时）→ 时间轴关键帧理解 → 结构拆解 → 手法指纹 → 手法迁移配方 → 迁移方案 → Markdown/JSON 证据 → Remotion 有声竖屏成片 → 质量报告 → 关键帧截图。
主推荐出片使用稳定商品图做开场可控推镜，避免图生视频在杯身、冰块和液体边缘产生逐帧抖动；CogVideoX 生成视频保留为补充镜头能力，不作为开场主视觉。新版模板会读取样例手法迁移配方，把源样例时间段、可迁移规则、素材槽位和补全方式直接显示到画面上，让评委能直接看到“样例手法 → 新内容映射 → 素材补全 → 视频重组”的结果。

演示时先播放 `submissions/final-coconut-latte/final-video.mp4`，再打开 `submissions/final-coconut-latte/final-demo-report.md` 展示证据链、质量报告和关键帧。

## 评委提问回答

### 和普通文案生成有什么区别？

普通文案生成只根据主题写内容。本项目先把样例拆成结构化创作规则，再迁移到新主题，所以能解释“为什么这样剪、哪个镜头承担什么功能、哪些元素可以替换”。

### 现在生成的视频是什么？

比赛 MVP 仍然优先验证可控创作链路，不做黑盒式文生视频。当前视频由 `RenderTimeline` 驱动，通过 Remotion 渲染 1080x1920 竖屏 MP4，用全屏场景、大字幕、素材位、漏光转场、运动模糊、颗粒层和合成音频展示“这套结构如何变成可剪的视频”。

### 没有模型 Key 时怎么演示？

系统内置本地 fallback 策略，能完整跑通样例拆解、结构迁移、多版本脚本、质量诊断、视频预览和导出。配置 OpenAI-compatible 模型后，可升级为真实多模态理解。

### 为什么说它可控？

方案输出由 Zod Schema 约束，前端展示的是结构化时间线。渲染阶段也只接受 `RenderTimeline`，模型不能生成或执行 Remotion 代码。

### 素材不足时怎么处理？

系统把视频结构拆成槽位，例如开头吸引、主体特写、使用过程、对比结果、背书证据和结尾 CTA。每个槽位会判断素材是否匹配，并给出结构重排、字幕补全、包装补全或复用现有素材等补全策略。
