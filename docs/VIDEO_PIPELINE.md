# 视频生成与手法迁移管线

本项目的目标不是“把一个视频模型生成的片段直接拼起来”，而是把样例视频里的剪辑结构抽象成可解释协议，再迁移到新商品、新主题和用户素材中。视频模型可以补素材槽位，但最终成片节奏、字幕、包装、转场、CTA 和音频卡点由结构协议与 Remotion 时间线控制。

## 1. 样例理解

输入可以来自上传视频、本地 `data/uploads` 视频、样例链接、人工观察文本、多样例补充文本。系统先抽取或接收这些信息：

- 媒体基础信息：时长、封面、分辨率、来源类型。
- 结构观察：Hook、节奏变化、镜头目的、字幕密度、包装元素、BGM/转场线索。
- 多模态模型输入：抽帧、ASR 文本、人工观察文本可以一起进入 LLM，输出必须通过 Zod Schema 校验。

## 2. 结构抽象

核心结构不是“内容文案”，而是可迁移的方法：

- `VideoStructureAnalysis`：记录样例的 Hook 类型、节拍图、字幕布局、包装风格、音乐卡点和 CTA。
- `TechniqueTransferRecipe`：把源样例时间段、源手法目的、可迁移规则、新片段目的、实际映射手法和素材状态放到同一行。
- `RenderTimeline`：把迁移结果转成可渲染的场景、字幕 token、素材层、转场和音频 cue。

## 3. 素材适配与缺口补全

用户素材会被拆成结构槽位，而不是简单当作附件：

- 开头吸引镜头、商品特写、使用过程、对比证据、场景 B-roll、结尾 CTA 都是独立槽位。
- 每个槽位有 `fit`、`impact`、`recommendedAssets` 和 `completionPlan`。
- 缺素材时优先使用结构重排、字幕/文案补全、标题条/卖点卡/贴纸补全、已有素材复用；AIGC 只作为补充画面或背景资产。

## 4. 视频模型边界

生成视频模型适合补中段 B-roll、氛围转场、局部动作片段，不适合未经筛选直接承担开场商品主视觉。原因是商品边缘、杯身、液体、文字和手部经常逐帧形变，评审会感知为抖动或不专业。

当前安全策略：

- `generated-video` 默认不能进入第 0 段 hero 或商品特写槽位。
- 只有带 `human-approved-hero-video` 风险标记的视频才能进入开场。
- 开场默认使用稳定图片 + Remotion 可控推镜 + 字幕/包装层，避免模型视频形变破坏第一印象。
- 视频模型输出进入 `VisualAssetManifest`，再由 `decideSceneAssetUsage()` 判定是否可用。

## 5. Remotion 稳定合成

最终 15 秒商业成片采用稳定合成，而不是证据层全堆在画面上：

- 开场首屏：稳定图片主视觉，关闭运动模糊和扫光，只保留轻微推镜。
- 中段 B-roll：使用 Remotion `OffthreadVideo` 承载可用视频素材，字幕、卖点卡和 CTA 仍由 React 组件控制。
- 转场：根据 `TechniqueTransferRecipe` 的源节拍强度生成 cut、fade、slide、wipe。
- 音频：用 `RenderAudioCue` 合成节拍、rise、hit、CTA cue，再通过 `<Audio>` 写入 MP4。
- 证据层：迁移配方、样例-结果对比、素材缺口和全要求验收导航保留在 Web 页面与 Markdown，最终广告片保持干净。

## 6. 工具协议与安全边界

- API 密钥只放 `.env`，`.env.example` 只保留变量名。
- 大模型输出必须进入结构化 JSON，再由 Schema 校验和本地 fallback 修复。
- 本地渲染产物、上传素材、数据库、`.next`、`renders`、`submissions` 不提交到 GitHub。
- 答辩时优先展示：多输入闭环、结构指纹、手法迁移配方、素材缺口与补全、竖屏分镜、最终有声 MP4。

## 7. 为什么不直接整段生成视频

整段视频生成可以作为未来增强，但比赛题目看重的是“结构能力的定义、抽象、迁移、补全和可解释”。如果直接让模型生成完整视频，系统很难证明：

- 学到了样例的哪些结构。
- 哪些结构被映射到新内容。
- 哪些素材槽位不足。
- 为什么用了某种补全策略。
- 用户如何修改 hook、节奏、包装或 CTA。

因此当前最佳路线是：视频模型补素材，Remotion 负责可控重组，LLM 负责理解与结构化决策，人机协同负责微调。
